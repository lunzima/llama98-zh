# pre-P6 x86 inefficiency rules for pentiumlint/cyrixlint.
#
# One rule per line, tab-separated:
#   PATTERN<TAB>PROCS<TAB>REASON
#
# PATTERN is the mnemonic(s) to flag, comma-separated. PROCS is the set
# of processors the rule bites on, comma-separated, from the family the
# rulebook targets (Pentium P5/P55C, Cyrix 6x86MX/MII, IDT WinChip C6/2,
# AMD K6/K6-2). A rule absent from a processor's set is fine there.
#
# The per-processor split is the whole point: inc/dec stall on P5's
# partial flags but K6 renames them, so one flat "inc is bad" rule would
# be wrong on half the family. The entries below are the known pre-P6
# inefficiencies; gcc's pentium.md / LLVM's X86SchedPentium.td are the
# reference to grow this table against, not memory.
#
# Soundness: every rewrite a rule implies is only correct when the flags
# it changes are dead. This table flags candidates; the reader proves.

inc,dec	p4	slow: the P4 trace cache stores 2 uops per inc/dec (read-modify-write), so add/sub wins. NOT p5/p6/k6 - gcc's X86_TUNE_USE_INCDEC keeps inc/dec there: the partial-flags stall is negligible next to the 1-byte encoding
