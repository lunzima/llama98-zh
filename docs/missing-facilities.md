**挡路的是两个缺陷，不是缺检查点**：

1. `n_fmt` 是个按格式写死的字典，**没有 T2 条目**，任何要 t2 的配方直接

## E. ARM 只有运行器，没有闸门

**证据**：`build/arm/` 只有 `build_engine.sh` 与 `run_qemu.sh`。
`run_qemu.sh` 跑二进制，**不做任何对拍**——本次那条 x86↔ARM 131072 字节

**同时**：ARM 侧**零个优化内核**（唯一适配是 `mmx_compat.h` 让

(2) 铁律八增补 ARM 行，把「ARMv5TE 没有 SIMD，所以只有标量 C + DSP 手写
汇编两格」这件事按它自己的举证标准写下来。

## H. 算子缺汇编实现（铁律八的覆盖断言本身也缺）

铁律八要求每个算子七种实现（标量 C + MMX/SSE/SSE2 × intrinsics/asm），
并要求一条**覆盖断言**：两个构建各自报告的档位取并集必须恰好覆盖
「格式 × 七种」，缺的格子要带原因。**那条断言不存在**，所以下面这张表是
手工数出来的，而不是任何东西自动报出来的——这本身就是缺失的设施之一。

### H1 / H2 —— 这张表现在由机器产出（2026-08-18）

**手工维护的那两张表是错的，而且错在高估。** 它们说 q4_1 / q6_1 / q8_0
有 gcc 的 128 组内核——**一个都没有**，`ops_kernel_dot.h` 里每一个
`dot128_*` 都是 Watcom 的 `#pragma aux`。没有任何闸门看得见这件事：
`test_dispatch_equiv.py` 那条覆盖断言查的是**档位名的并集**，而
「某个格式缺某个内核」不改变档位名集合。

所以这张表不再手写。`llama98 --kernel-matrix` 由 `lz_kernel_matrix()`
从 `LZ_ROW_*` 表直接产出，两个构建取并集：

```
format mmxI sseI sse2I mmxA sseA sse2A  g128
q8_0   x    .    x     x    .    x      G
q4_1   x    .    x     x    .    x      G
q6_1   x    .    x     x    .    x      G
q16_0  x    .    x     x    .    x      G
t2     x    .    x     x    .    x      .
```

**H1 完成**：五个格式的四个非 SSE1 格全齐。此前「T2 缺」是按符号名检索
的误判——它的 SSE2 intrinsics 内联在 `row_t2_sse2_intrin` 里，没有独立符号。

**H2 的真实状态**：`g128` 那一列 Watcom 侧四个格式有、T2 没有，**gcc 侧一个都没有**。
两个空的理由不同类，分开记：

- **T2 无可摊销，是结构性的。** 对照 q6_1——它同样解 2 位平面**却有** 128 组内核，
  因为它跨四个子块提升了两个掩码常量（0x0F 与 0x03）加一个零寄存器。T2 的解包
  只有一个零寄存器加三个立即数移位，把零提升出去只是把 `pxor mm2,mm2` 换成
  `movq mm2,mm7`，一条换一条；每个子块自带 2 位平面、自带累加器、自带折叠。
  它的 128 组内核会发出与四次 32 调用**逐条相同**的指令序列。
- **gcc 侧是「没写」，不是「没东西可提供」。** 汇编版手工提升的那些循环不变量，
  编译器本来就会提升；**但「手写版会不会与编译器产物不同」没有量过**，所以不许
  写成结构性空缺。

**闸门 `tests/test_kernel_matrix.py`**（训练树）：空格必须在登记表里带理由，
**而且反向也查**——已经填上的格子如果还留着「为什么空」的理由，同样红。
变异矩阵 `.prof/mut_kernel_matrix.py` 三个变异各只红自己那条：删掉
t2 的 sse2-intrin（此前所有闸门都看不见）、给 t2 填上 g128 而不撤理由、
从矩阵里删掉一个格式。

### H3. 五个算子的格子

| 算子 | 七格里有几格 | 备注 |
|---|---|---|
| `lz_quantize_q8` amax 扫描 | **5/7**（2026-08-18） | 标量 C + MMX/SSE2 各两侧；**SSE1 那格结构性为空**，理由已写下 |
| `lz_rmsnorm` 输出循环 | **3/7**（2026-08-18） | 标量 C + SSE/SSE2 两侧共用一份（`mulps`/`addps` 是 SSE1，SSE2 加的东西这里用不上）；**MMX 那格结构性为空**——MMX 是纯整数指令集。平方和那半仍是标量 |
| `lz_causal_conv1d_step` | 0 | **不是不可能，是没写**——见下方「跨通道」一段 |
| `lz_rmsnorm_gated` | 0 | 输出循环逐元素调 `lz_silu`，跟着 silu 走 |
| `lz_softmax` max 扫描 + 归一化 | **3/7**（2026-08-18） | 两处都是 SSE1（`maxps` / `mulps`），MMX 那格结构性为空。**求和那半仍是标量** |
| `lz_silu` / `lz_sigmoid` | 0 | **结构性**：两条路都要查表——定点档是 Q15 表，浮点档的 `lz_exp` 是 32 项 `2^(k/32)` 表——而 MMX/SSE2 都没有 gather，四条 lane 的索引各不相同就没法一次取 |

**这里有一条把剩下四个卡住的结构性事实，值得单独写下**：铁律二要求七格之间
逐位一致，而**浮点求和的向量化必然改结合顺序**，所以 conv 的 MAC、RMSNorm 的
平方和、softmax 的求和都不能直接向量化——要做只能另开一个自身逐位一致的独立档
（形如本会话那四个定点旋钮）。

**能直接向量化的是「逐元素」与「精确归约」两类。** amax 属于后者：max 精确且
可结合，lane 顺序改不了答案，所以它是这五个里唯一能立刻拿到逐位一致 SIMD 的。
掩掉符号位后所有值非负，于是 MMX/SSE2 只有的**有符号** 32 位比较也正确。

**conv1d 有第三条路：跨通道，不跨抽头。** 卷积是 **depthwise** 的——通道 c 的历史
只和通道 c 的抽头相乘——所以四个**通道**并行时，每个通道的 k 项求和**顺序不变**，
逐位一致成立。挡路的是布局而非算术：权重是 `w[c*k + j]` 通道优先，k=4 时四个通道
的权重是连续的 16 个 float，一次 4×4 转置（`_MM_TRANSPOSE4_PS`，SSE1）就变成抽头优先；
历史是 `state[c*hist + j]`，hist=3 不是 4 的整数倍，那一半要另想。**没写。**

按同一判据，剩下明确可做的只有这一项。silu/sigmoid 那两格是真的没有指令可用。

### H4. ARM 的表 —— 已补（2026-08-18）

## 建议次序

1. **D**（降级闸门搬进导出器）——最小，且本次已写好一半，不补下一次还会中同一个坑
2. **F**（查清 subnormal 保证）——它挡着 f24 提案，且是铁律文本与代码不符
3. **H4 + E**（铁律八补 ARM 行；ARM 对拍固化）——补 ARM 行是纯文本，但它决定 CE 的内核工作有没有验收标准
4. **G**（最小 CI）
5. **H3**（五个零实现算子）——从 `conv1d` 起，它是唯一「无 SIMD、无定点、4 抽头 MAC」的一个，且 GDN 定点档已证明模式与收益量级
6. **A**（探针归位）——最严重，但要用户先裁定「铁律引用的取证工具算不算 testsuite」
7. **H2**（T2 的 128 组内核）——依赖 B 有可跑的 t2 模型才谈得上验收
8. **B/C**（出货配方与 T2 的端到端）——依赖 A 与一个 QAT 检查点

**次序里有一条约束不是工作量**：H1/H2/H3 的任何一格都不许在没有闸门时
落地。铁律二要求新汇编先在探针里对标量跑十万量级随机+极值，过了再搬进
`src/`——而那些探针正是 **A** 卡着的东西。所以 **A 是 H 的前置**，
虽然它排在后面（等裁定）。
